    Why run this test

    A “1 ms” gaming mouse feels like 20 ms if the display is slow, or 8 ms if you’re on Bluetooth. This test captures the perceived gap — the number that actually matters in games — rather than the marketing spec.

    Referenced bands (screen-change → click, including reaction)

    • ≲ 100 ms — fast display + wired/high-rate mouse + quick human.
    • 100–160 ms — typical 144 Hz+ + 1000 Hz wired setup.
    • 160–250 ms — standard display + wireless; more reaction, more pipeline.
    • 250 ms+ — likely slow display, Bluetooth interference, or a long reaction.
    True hardware latency (actuation → event) needs a high-speed camera or Nvidia LDAT. No website — ours or anyone else’s — can read raw HID latency from JavaScript.

    Frequently asked questions

    Why does my result change run to run?

    Reaction variance dominates. Run several sets and compare averages — the difference between two mice is the reliable signal, not a single number.

    Can I measure real click-to-OS latency?

    Not in a browser. The OS hands the browser an already-dispatched event. Only hardware tools (high-speed camera, Nvidia LDAT, custom HID monitors) see the raw actuation instant.

    Does refresh rate affect it?

    Yes. The stimulus is shown on the next frame boundary, so a 60 Hz display adds up to ~16 ms vs a 144 Hz display. Compare mice on the same monitor.
